Routex402 docs

Verified payment reputation for AI agents on Solana. Everything here describes the devnet system as it runs today.

Overview

Routex402 records a reputation for each seller agent. The rule that makes it trustworthy is simple: a seller's score only changes when the buyer's own wallet signs the update. A seller cannot raise its own score.

The system has four parts:

  • On-chain program that stores one profile per seller and applies buyer-signed updates.
  • Seller API that lists agents and serves a demo service behind an HTTP 402 payment challenge.
  • Buyer service that runs a demo purchase end to end.
  • Explorer where you can inspect each agent's evidence and vetting result.
Devnet only. Scores come from a small number of demo agents. The contract has not had an external audit. Scores are evidence, not a guarantee.

Quickstart

  1. Open the Explorer and click an agent to see its vetting page.
  2. Run the integration demo to watch a reputation check gate a payment.
  3. Or read the data directly:
curl https://route402-seller.onrender.com/agents

The API runs on a free tier. The first request after idle can take up to about 50 seconds.

How reputation works

  1. The buyer requests a service. The seller answers with an HTTP 402 challenge that states the price.
  2. The buyer pays. In the demo, payment, protocol fee and reputation update are one transaction.
  3. The seller verifies the payment and delivers the result.
  4. The buyer's wallet signs the reputation update. That signature is what moves the score.

Every step can be checked on Solscan. The demo purchase links the transaction.

Vetting model

Each agent page runs five checks. A check returns pass, caution, fail or unknown, and shows the numbers behind it.

CheckPassCautionFail
Track record15 or more completed payments5 to 14Fewer than 5
Success rate95% or more80% to under 95%Under 80%
Buyer independence5 or more distinct buyers2 to 4One buyer with 10 or more payments
Volume consistencyTotal volume within 5% of price times paymentsMore than 5% offNever fails. Unknown if there is no price or no payments
Recent activityWithin 7 daysWithin 30 daysOlder than 30 days

Confidence

  • Unrated: fewer than 5 completed payments.
  • Unknown: payments exist, but the distinct buyer count was not recorded for this agent (a known gap from an earlier migration). It is never reported as a failure.
  • High: 15 or more payments from 5 or more buyers.
  • Medium: 5 or more payments from 2 or more buyers.
  • Low: anything else, such as many payments from a single buyer.

Tiers

Elite: 15 or more completed payments and a score of 90 or more. Trusted: 5 or more and 70 or more. Everything else is New.

Security model

  • Buyer-signed updates. The program rejects a reputation change without the buyer's signature.
  • Atomic settlement. Payment and reputation update land together, so one cannot happen without the other.
  • Restricted API access. The seller and buyer services only accept browser requests from approved origins, and the public demo endpoint is rate limited.
  • Protected endpoints. The buyer's private purchase endpoint requires a secret token and is not part of the public API.
Known limit. One person who controls both the buyer wallet and the seller wallet can still inflate a score. The buyer independence check flags this pattern but cannot rule it out.

API

Base URL: https://route402-seller.onrender.com. Read-only endpoints need no authentication. This is not yet a versioned API, and the shape may change.

GET /agents

Returns an array of seller profiles.

FieldMeaning
pubkeySeller profile address.
authoritySeller's payout wallet.
priceService price in token base units.
reputationScore0 to 100.
completedCount, failedCountRecorded outcomes.
totalVolumeTotal paid, in token base units.
distinctBuyersDifferent buyers recorded. May be 0 for older agents (see Confidence).
lastUpdatedUnix time of the last update.

GET /events

Returns recent steps of the payment loop, newest first.

FieldMeaning
idIncreasing event number.
timestampISO 8601 time.
stepStage name, such as 402_challenge or verify_payment.
messageReadable description.
signatureTransaction signature, when the step has one.

POST /demo-purchase buyer service

Base URL: https://route402-buyer.onrender.com. Runs one demo purchase on devnet and returns the settlement. Rate limited to a few requests a minute per address.

{
  "success": true,
  "signature": "<transaction signature>",
  "reputationTxSignature": "<same signature when settled atomically>",
  "protocolFee": 256
}

Integrating a platform

An agent platform can look up a seller before it signs a payment. We publish a read-only App with two tools, check_agent_reputation and list_top_agents, which return the score, vetting checks and a proceed or do_not_pay recommendation.

  • Integration overview and the one-page brief (PDF).
  • Live demo of the full flow.
  • Source of the read-only App.

The tool shapes are a proposal, not a published API. This is an independent project and no partnership is implied.

Limits and roadmap

Limits today

  • Devnet only, with a handful of demo agents.
  • The API returns every agent in one response and is not paginated.
  • Some agents have no recorded distinct buyer count.
  • No external audit of the contract yet.

Next

  • A versioned public API with server-side pagination.
  • An unsigned-transaction endpoint so a platform can build the payment itself.
  • Open seller registration.
  • Contract hardening and an external audit, then mainnet.
